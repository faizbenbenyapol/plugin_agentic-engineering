# ทำหลายแบบให้ผู้ใช้สลับดู (UI variants)

ดัดแปลงจาก prototype ของ mattpocock/skills ใช้เมื่อทิศทางหน้าตายังไม่ชัด ผู้ใช้ขอ "ดูหลายแบบ" หรือ design plan มีสองทางที่ดีพอกันและเลือกไม่ได้ด้วยเหตุผล การได้กดสลับดูของจริงตัดสินเร็วกว่าการบรรยาย mockup ในแชท

## จำนวน (ปรับให้เข้ากับโควตา Pro)

- ค่าเริ่มต้น **2 แบบ** ผู้ใช้ขอเพิ่มได้สูงสุด 3 ทุกแบบคือโค้ดที่ต้องเขียนจริง
- แต่ละแบบต้อง **ต่างกันที่โครงสร้าง** ไม่ใช่แค่สีหรือคำ: layout ลำดับความสำคัญของข้อมูล หรือการกระทำหลักต้องต่างกัน ถ้าสองแบบออกมาคล้ายกัน ให้ทำแบบหนึ่งใหม่โดยห้ามใช้โครงของอีกแบบ
- ทุกแบบผ่านกติกาของ `anti-ai-ui` และใช้ข้อมูลจริงเหมือนกัน

## รูปแบบ

- **มีหน้าเดิมให้วางอยู่แล้ว (ใช้แบบนี้ก่อน):** แสดงทุกแบบบน route เดิม เลือกด้วย `?variant=A` การดึงข้อมูล สิทธิ์ และ layout รอบนอกคงเดิม เปลี่ยนเฉพาะส่วนที่กำลังออกแบบ หน้าตาที่อยู่ติดกับส่วนอื่นของแอปจริงตัดสินได้ดีกว่าหน้าว่าง
- **ไม่มีที่ให้วาง:** route ชั่วคราวที่มีคำว่า `prototype` ในชื่อตามธรรมเนียม routing ของโปรเจกต์ หรือไม่มีแอปเลยให้ทำไฟล์ HTML ไฟล์เดียวที่เปิดได้ด้วยการดับเบิลคลิก
- **แถบสลับ** ลอยกลางล่าง: ← ชื่อแบบ → และปุ่มลูกศรบนคีย์บอร์ดใช้ได้ (ยกเว้นตอนพิมพ์ใน input) หน้าตาต่างจากดีไซน์ให้เห็นชัดว่าไม่ใช่ส่วนของงาน ซ่อนเมื่อ build production
- **ห้ามต่อกับการเขียนข้อมูลจริง** ปุ่มที่บันทึกให้ชี้ไปที่ stub

## ส่งให้ผู้ใช้และเก็บผล

1. ส่งลิงก์หรือคำสั่งรัน พร้อมบอกหนึ่งบรรทัดต่อแบบว่ามันตัดสินใจต่างกันตรงไหน ถ้า screenshot ได้ ส่งภาพแบบละหนึ่งภาพ
2. คำตอบที่มีประโยชน์ที่สุดมักเป็น "เอาหัวของ A กับรายการของ B" ให้ถามแบบเปิดแบบนี้ด้วย
3. ได้คำตอบแล้ว จดลงไฟล์รีไควร์เมนต์หัวข้อ 8: เลือกแบบไหน เพราะอะไร และส่วนที่ยืมจากแบบอื่น
4. เขียนแบบที่ชนะใหม่ให้เป็นโค้ดจริงตามมาตรฐาน (โค้ด variant เขียนแบบ prototype ไม่มี test) แล้วลบแบบที่แพ้ แถบสลับ และ route ชั่วคราวออกจาก branch งาน ภาพของแบบที่ชนะคือภาพอ้างอิงที่อนุมัติแล้ว ใช้เทียบตอนตรวจ
