# แคตตาล็อกลายเซ็น "งาน AI" และทางแก้

อ่านไฟล์นี้ก่อนเขียนโค้ด UI ทุกครั้ง แต่ละข้อมี **ลายเซ็น** (สิ่งที่โมเดลมักทำโดยอัตโนมัติ) และ **ทางแก้** (ทำอะไรแทน)

หมายเหตุสำคัญ: ทุกข้อในนี้ "ใช้ได้" กับบาง brief ปัญหาไม่ใช่ตัวมันเอง แต่คือการที่มันโผล่มาทุกครั้งไม่ว่างานจะเป็นเรื่องอะไร ถ้าผู้ใช้สั่งมาตรง ๆ ว่าอยากได้แบบนี้ — ทำตามผู้ใช้

## 1. สีและพื้นผิว

**ลายเซ็น**
- gradient น้ำเงิน→ม่วง (`#6366F1` → `#8B5CF6`, indigo-500→violet-500) เป็นสีแบรนด์
- ใช้ Tailwind palette ดิบทั้งชุด: `slate-900` เป็นหัวข้อ `slate-500` เป็นเนื้อความ `slate-50` เป็นพื้น
- ครีมอุ่น `#F4F1EA` + ส้มดินเผา `#D97757` (สีนี้คือสี accent ของ Claude เอง ยิ่งเป็นการฟ้อง)
- ดำเกือบสนิท `#0B0B0B` / `#111` + accent เขียวมะนาวหรือส้มแดงจัดสีเดียว
- glassmorphism: `backdrop-blur` + ขอบขาวโปร่ง + การ์ดลอย
- blob เบลอเรืองแสงหลังพื้นหลัง หรือ radial gradient มุมจอ
- gradient บนตัวอักษร headline (`bg-clip-text`)
- ทุกอย่างมี `shadow-lg` เงาเทาอมฟ้าเหมือนกันหมด

**ทางแก้**
- ดึงสีจากโลกจริงของเรื่องนั้น: สีหมึกใบเสร็จ สีป้ายเตือนในโรงงาน สีชุดพนักงาน สีวัสดุจริง แล้วปรับให้ contrast ผ่าน
- ตั้งชื่อสีตามเรื่อง ไม่ใช่ `primary` / `secondary` — เช่น `ink`, `receipt`, `warning-tape`, `night-shift`
- ใช้สีน้อยแต่ใช้ให้กล้า: base เป็นกลาง 2–3 ค่า + accent เดียวที่ใช้เฉพาะสิ่งสำคัญจริง ๆ
- แทนที่จะทำ gradient ให้ลองพื้นผิวอื่น: สีทึบตัดกันแรง, เส้นบาง, พื้นหลังกริด, ขอบหนา, สีพื้นแบ่งโซนเป็นบล็อก
- เงา: ถ้าไม่มีเหตุผลว่าของชิ้นนี้ "ลอย" จริงไหม ให้ใช้เส้นขอบหรือสีพื้นต่างแทน และถ้าใช้เงา ให้ระดับต่างกันตามลำดับความสำคัญจริง

## 2. ตัวอักษร

**ลายเซ็น**
- หยิบ Inter / Poppins / Plus Jakarta Sans / Geist / Manrope โดยไม่ได้เลือก
- headline ใหญ่มาก + `tracking-tight` + `font-bold` + จัดกลาง
- eyebrow ตัวเล็ก ALL CAPS จัด letter-spacing กว้าง เหนือทุกหัวข้อ
- เน้นคำเดียวใน headline ด้วยสีหรือ gradient ต่างจากคำอื่น
- ฟอนต์ mono ใช้กับ label เล็ก ๆ ทั้งที่ไม่ใช่ข้อมูลเชิงเทคนิค
- เนื้อความ 16px สีเทากลาง ๆ ทุกที่ ไม่มีลำดับชั้น
- คั่นข้อมูลด้วยจุดกลาง `A · B · C` และ `WORD — คำอธิบาย`

**ทางแก้**
- เลือกฟอนต์เพราะบุคลิก ไม่ใช่เพราะปลอดภัย ตัวอย่างที่ใช้ได้จริงและไม่โหล: Söhne, Untitled Sans, GT America (เชิงพาณิชย์); Space Grotesk, Instrument Sans, Bricolage Grotesque, Fraunces, Newsreader, Source Serif 4, Libre Franklin, Public Sans, IBM Plex family, Archivo, Chivo, Redaction (ฟรี)
- ใช้ตระกูลเดียวหลายน้ำหนักก็เพียงพอและมักดูตั้งใจกว่า 2 ตระกูลที่เลือกมั่ว
- ถ้าใช้ 2 ตระกูล ต้องต่างกันชัดจนคนไม่ออกแบบก็เห็น (serif คู่ grotesk, ไม่ใช่ sans สองตัวที่หน้าเหมือนกัน)
- ตั้ง type scale จริง (เช่น 1.25 หรือ 1.333) แล้วใช้ตามนั้น อย่าสุ่มขนาด
- ให้ typography เป็นตัวดีไซน์เอง: headline ที่ตัดบรรทัดตั้งใจ, ตัวเลขขนาดใหญ่เป็นตัวเอก, การจัดชิดขอบที่กล้า ดีกว่าใส่ของประดับรอบ ๆ
- ความยาวบรรทัดไม่เกิน ~75 ตัวอักษร serif ยาวได้กว่าเล็กน้อยและต้องการ line-height มากกว่า

## 3. โครงหน้าและ layout

**ลายเซ็น** — โครง landing page อัตโนมัติ:
```
hero จัดกลาง (headline + subtitle + ปุ่ม 2 ปุ่ม)
→ logo cloud "trusted by"
→ feature 3 คอลัมน์ (ไอคอนกลม + หัวข้อ + 2 บรรทัด)
→ แถบสถิติ 4 ตัวเลขใหญ่
→ ภาพสลับซ้าย-ขวา
→ testimonial การ์ดพร้อมรูปกลม
→ ตาราง pricing 3 ระดับ ตรงกลางมีป้าย "Popular"
→ FAQ accordion
→ CTA แถบเต็มจอสีตัด
→ footer 4 คอลัมน์
```
- ทุก section กว้าง `max-w-7xl` จัดกลาง padding เท่ากันหมด
- ทุกอย่างอยู่ในการ์ดมน `rounded-2xl` เท่ากันทั้งหน้าไม่ว่าจะสำคัญแค่ไหน
- ระยะห่างระหว่าง section เท่ากันเป๊ะทุกช่วง จังหวะการอ่านจึงแบน

**ทางแก้**
- เริ่มจากถามว่า "คนเข้ามาหน้านี้เพื่ออะไร" แล้วเรียงลำดับตามนั้น ไม่ใช่ตามสูตร
- hero ควรเปิดด้วยสิ่งที่เป็นตัวแทนของเรื่องนี้ที่สุด — อาจเป็นตัวเลขจริง ตารางจริง ภาพจริง เดโมที่กดได้ หรือแค่ประโยคเดียวที่คมมาก
- ทำลายกริด: ให้บาง section เต็มขอบจอ บาง section แคบมาก บาง section ชิดซ้ายไม่จัดกลาง
- ใช้จังหวะระยะห่างต่างกันเพื่อบอกลำดับความสำคัญ ของสำคัญได้ที่ว่างเยอะ ของรองอัดชิด
- radius ต้องมีเหตุผล: ถ้าใช้มน ให้มนต่างระดับตามลำดับ หรือเลือก 0 ไปเลยทั้งหน้า
- แทนการ์ด ลองใช้: ตาราง, รายการที่มีเส้นคั่น, บล็อกสีทึบ, การวางซ้อน, ขอบหนาแบบกรอบ

## 4. ส่วนประกอบ

**ลายเซ็น**
- ปุ่ม 2 ปุ่มติดกันเสมอ: หลักสีทึบ + รองแบบ ghost เขียนว่า "Learn more →"
- badge/pill มนสุด ๆ ใส่ทุกที่ รวมถึงที่ไม่ต้องการ
- avatar กลม + ชื่อ + ตำแหน่ง ในทุก testimonial
- ตารางราคา 3 ระดับ ตรงกลางถูกไฮไลต์เสมอ
- toast มุมขวาบนพร้อมไอคอนติ๊กเขียว
- ทุก input มีขอบมน สีเทาอ่อน `focus:ring-2 ring-indigo-500`

**ทางแก้**
- ปุ่มเดียวก็พอถ้ามีทางเดียวที่ควรไป การใส่ปุ่มรองมาคู่กันแปลว่ายังตัดสินใจไม่ได้ว่าคนควรทำอะไร
- ข้อความบนปุ่มบอกสิ่งที่จะเกิดขึ้น: "บันทึกตาราง", "ส่งใบเสนอราคา" ไม่ใช่ "Submit" หรือ "Get Started"
- ชื่อ action ต้องเหมือนกันตลอดเส้นทาง ปุ่ม "เผยแพร่" ต้องได้ toast ว่า "เผยแพร่แล้ว"
- badge ใช้เมื่อสถานะนั้นมีความหมายจริง และรูปทรงควรสื่อความหมาย (สถานะเร่งด่วนไม่ควรหน้าตาเหมือนแท็กหมวดหมู่)
- form: label อยู่ด้านบนเสมอ, error อยู่ติดช่องที่ผิด, บอกรูปแบบที่ต้องการก่อนผู้ใช้พิมพ์ผิด ไม่ใช่หลังจากนั้น

## 5. ไอคอนและภาพ

**ลายเซ็น**
- lucide/heroicons เส้นบางเท่ากันหมด ใส่ในวงกลมพื้นสีอ่อน
- ไอคอนเลือกแบบพอไปวัดไปวาน (Zap = เร็ว, Shield = ปลอดภัย, Sparkles = AI)
- อีโมจิแทนไอคอนใน bullet
- รูป stock คนยิ้มในออฟฟิศ / ภาพ 3D abstract สีม่วง
- placeholder สีเทามีตัวอักษร "Image"

**ทางแก้**
- ถ้าไอคอนไม่ได้เพิ่มความเข้าใจ ให้ตัดทิ้ง ข้อความอย่างเดียวมักชนะ
- ถ้าจะใช้ ให้เลือกชุดที่มีบุคลิก (Phosphor หลายน้ำหนัก, Material Symbols ปรับ axis, หรือวาด SVG เองไม่กี่ตัวสำหรับสิ่งที่เป็นแกนของโปรดักต์)
- แทนภาพ stock: ใช้ข้อมูลจริงเป็นภาพ (ตาราง กราฟ สลิป การ์ดข้อมูล), ใช้ typography เป็นภาพ, ใช้บล็อกสี, ใช้แผนภาพที่อธิบายของจริง
- ถ้าไม่มีรูปจริง ให้ออกแบบพื้นที่นั้นให้ไม่ต้องใช้รูป ดีกว่าใส่ placeholder

## 6. Motion

**ลายเซ็น**
- ทุก section fade-in + เลื่อนขึ้นตอน scroll
- ทุกการ์ด hover แล้วยกขึ้น + เงาเข้มขึ้น
- ตัวเลขนับขึ้นตอนเลื่อนถึง
- ลูกศร `→` ในปุ่มขยับตอน hover
- gradient เคลื่อนช้า ๆ ตลอดเวลา

**ทางแก้**
- motion ที่ตอบการกระทำของคน (เปิด ปิด ขยาย ยืนยัน ลบ) มีประโยชน์เสมอ เพราะมันบอกว่าอะไรเปลี่ยนไป — เก็บไว้
- motion ที่เกิดเองโดยคนไม่ได้ทำอะไร ให้เหลือ **จุดเดียวทั้งหน้า** และต้องเป็นจุดที่ตั้งใจให้คนมอง
- ระยะเวลา 120–240ms สำหรับ UI ทั่วไป ยาวกว่านั้นคนเริ่มรู้สึกว่าเว็บช้า
- ใส่ `@media (prefers-reduced-motion: reduce)` เสมอ

## 7. Copy

**ลายเซ็น**
- "Seamlessly integrate", "Effortlessly manage", "Supercharge your workflow", "Built for the modern team", "The all-in-one platform for..."
- ปุ่ม "Get Started Free" / "Learn More →" / "Book a Demo"
- หัวข้อฟีเจอร์ 2–3 คำ + คำอธิบาย 2 บรรทัดที่ไม่ได้บอกอะไรเพิ่ม
- สถิติที่ไม่มีที่มา: "99.9% uptime", "10,000+ happy users"
- error ว่า "Something went wrong. Please try again."
- ภาษาไทย: "ยกระดับธุรกิจของคุณสู่อีกขั้น", "โซลูชันครบวงจร", "ง่าย ๆ เพียงปลายนิ้ว"

**ทางแก้**
- เขียนสิ่งที่เกิดขึ้นจริง มีของจริง มีตัวเลขจริง: "สรุปยอด 3 สาขาให้ทุกเช้า 6 โมง" ชนะ "จัดการธุรกิจอย่างไร้รอยต่อ"
- error ต้องตอบ 2 อย่าง: เกิดอะไรขึ้น และต้องทำอะไรต่อ — "อัปโหลดไม่สำเร็จเพราะไฟล์เกิน 10 MB ลองบีบอัดแล้วส่งใหม่"
- empty state คือคำเชิญให้ลงมือ ไม่ใช่คำแจ้งว่าว่างเปล่า
- ใช้ voice active, sentence case, คำกริยาธรรมดา, เรียกสิ่งต่าง ๆ ตามที่ผู้ใช้เรียก ไม่ใช่ตามที่ระบบสร้างไว้
- ตัดคำที่ลบแล้วความหมายไม่เปลี่ยนออกให้หมด

## 8. Dashboard และ data

**ลายเซ็น**
- แถวการ์ด KPI 4 ใบบนสุด ทุกใบมีลูกศรเขียว/แดง + "+12.5% from last month"
- กราฟเส้น gradient ใต้เส้น + โดนัทชาร์ต + bar chart ที่ไม่ได้ช่วยตัดสินใจอะไร
- ตารางที่ทุกคอลัมน์กว้างเท่ากันและจัดชิดซ้ายหมด รวมทั้งตัวเลข
- sidebar ซ้าย + topbar + ค้นหากลาง ๆ เหมือนกันทุกโปรเจกต์

**ทางแก้**
- ถามว่า "คนเปิดหน้านี้เพื่อจะตัดสินใจอะไร" แล้วให้ตัวเลขที่ตอบคำถามนั้นเด่นที่สุดเพียงตัวเดียว ที่เหลือรอง
- ตัวเลข: จัดชิดขวา, ใช้ตัวเลขความกว้างเท่ากัน (`font-variant-numeric: tabular-nums`), ทศนิยมเท่ากันทั้งคอลัมน์
- เลือกชนิดกราฟตามคำถาม: แนวโน้ม→เส้น, เทียบปริมาณ→แท่ง, สัดส่วน→แท่งซ้อนหรือ 100% bar (โดนัทอ่านยากเกือบทุกกรณี)
- ใส่บริบทที่ทำให้ตัวเลขมีความหมาย: เทียบกับเป้า เทียบกับช่วงเดียวกันปีก่อน ไม่ใช่ % ลอย ๆ
- ตารางที่ดีมักมีค่ามากกว่ากราฟสวย ๆ ถ้าคนต้องดูของทีละรายการ

## 9. ทางออกเวลาตัน

ถ้าคิดไม่ออกว่าจะทำให้ไม่โหลยังไง ลองหยิบข้อใดข้อหนึ่ง:

- **ยืมจากสื่อสิ่งพิมพ์ของวงการนั้น** — เมนูอาหาร ตารางเดินรถ ใบเสร็จ แบบฟอร์มราชการ ป้ายในโรงพยาบาล สูจิบัตร ปกอัลบั้ม
- **ให้ข้อมูลเป็นพระเอก** — แทนที่จะบรรยายว่าโปรดักต์ทำอะไร แสดงของจริงที่มันผลิตออกมาเลย
- **เลือกข้อจำกัดหนึ่งข้อแล้วอยู่กับมัน** — สีเดียว, ไม่มีมุมมน, ไม่มีเงาเลย, ตัวหนังสือล้วนไม่มีรูป, ทุกอย่างชิดซ้าย
- **สลับสัดส่วน** — สิ่งที่ปกติเล็กทำให้ใหญ่มาก สิ่งที่ปกติใหญ่ทำให้เล็กลง
- **ทำหน้าจอที่ยากที่สุดก่อน** — หน้าที่ข้อมูลเยอะที่สุดหรือ flow ที่ซับซ้อนที่สุด ดีไซน์ที่รอดจากหน้านั้นจะใช้กับหน้าที่ง่ายกว่าได้เสมอ ส่วนดีไซน์ที่เกิดจากหน้า landing สวย ๆ มักพังทันทีที่เจอของจริง
