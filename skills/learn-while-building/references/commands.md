# คำสั่งของโหมดสอน

อ่านไฟล์นี้เมื่อผู้ใช้พิมพ์คำสั่งในตาราง คำสั่งเปลี่ยนความลึกและเปิด/ปิดโหมดอยู่ใน SKILL.md แล้ว

| ผู้ใช้พูด | ทำ |
| --- | --- |
| "ขยาย" "ลึกอีก" | อธิบายแนวคิดหรือการเปลี่ยนล่าสุดเพิ่มหนึ่งชั้น: กรณีขอบ เหตุผล ทางเลือกที่ไม่เลือก |
| "ง่ายกว่านี้" "ไม่เข้าใจ" | ถามสั้น ๆ ว่าติดตรงไหนถ้าไม่ชัด แล้วอธิบายใหม่จากจุดนั้น ใช้ค่าจริงไหลผ่านโค้ดทีละบรรทัด ห้ามแค่พูดเดิมให้สั้นลง |
| "อธิบายที่ทำไป" | เขียน "ทำอะไรไปบ้าง" ฉบับเต็มของงานล่าสุด แม้จบงานไปแล้ว |
| "อธิบายไฟล์นี้" | อ่านแบบแคบ แล้วเล่า ภาพรวม → ข้อมูลไหลยังไง (ตามค่าจริงหนึ่งตัว) → ทำไมเป็นแบบนี้ |
| "ทวน" "สรุปที่เรียน" | อ่าน `.learning/concepts.md` แล้วสรุปแนวคิด สถานะ และการเชื่อมกัน |
| "ทดสอบฉัน" | ถาม 3–5 ข้อจากโค้ดของเขาทีละข้อ ตรวจด้วยการรันเมื่อทำได้ ตอบถูกให้ขยับสถานะแนวคิด ตอบผิดให้อธิบายจากคำตอบของเขาว่าเข้าใจคลาดตรงไหน |
| "ให้ฉันลองเขียน" | เลือกชิ้นเล็กที่มีการตัดสินใจจริง ใส่ `TODO(human)` บอกบริบทและสิ่งที่ต้องชั่งน้ำหนัก แล้วหยุดรอ เขาเขียนเสร็จให้รันตรวจและ feedback ห้ามแก้ทับเงียบ ๆ |
| "จดบันทึก" | เปิดใช้ `.learning/journal.md` ใน session นี้ |
| "เก็บบันทึก" | commit `.learning/` ขึ้น branch งาน โดยลบ `.learning/` ออกจาก `.git/info/exclude` ก่อน |

## สมุดบทเรียน

รูปแบบไฟล์อยู่ใน `templates.md` (โฟลเดอร์เดียวกัน)

- สร้าง `.learning/` เมื่อมีแนวคิดแรกให้บันทึก แล้วเพิ่มลง `.git/info/exclude` และบอกผู้ใช้หนึ่งบรรทัด
- บนคลาวด์ `.learning/` จะหายเมื่อ VM ถูกเรียกคืนถ้าไม่ commit ครั้งแรกที่สร้างให้บอกว่าสั่ง "เก็บบันทึก" ได้
- อัปเดตเฉพาะแถวที่เปลี่ยน ขยับสถานะเมื่อมีหลักฐานว่าเข้าใจ แนวคิดที่ "คล่อง" ย้ายไปโปรไฟล์
- ไม่เก็บข้อมูลลับลงสมุด
