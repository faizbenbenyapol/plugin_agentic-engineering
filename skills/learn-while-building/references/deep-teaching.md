# ระดับสอนละเอียด

ใช้เมื่อผู้ใช้สั่ง "สอนละเอียด" "สอนทุกขั้น" หรือโปรไฟล์ตั้ง `ความลึกที่ชอบ: ละเอียด` เป็นส่วนที่เพิ่มจากระดับปกติใน SKILL.md (สามจังหวะ บล็อกสอน และ "ทำอะไรไปบ้าง" ยังใช้ครบ) กินโควตาเพิ่มชัดเจน จึงไม่ใช่ค่าเริ่มต้น

## จังหวะที่สอนเพิ่ม

ระดับปกติสอนเมื่อเจอแนวคิดใหม่ ระดับนี้สอนทุกจังหวะในตารางที่มีอะไรให้เรียน ใช้ agentic-engineering อยู่ให้ผูกกับขั้นของ playbook:

| จังหวะ | สอนอะไร |
| --- | --- |
| สืบสวนเสร็จ | แผนที่งานฉบับเต็ม: วาดแผนภาพเสมอเมื่อมี 2 ส่วนขึ้นไปคุยกัน และตามค่าจริงหนึ่งตัวไหลผ่านระบบตอนนี้ (ก่อนแก้) |
| ตั้งชื่อรูปร่างข้อมูล / ร่างแบบเสร็จ | เทียบโครงสร้างที่เลือกกับทางที่ง่ายกว่า โดยเขียนโค้ดสั้น ๆ ให้เห็นทั้งสองแบบ แล้วบอกว่าแบบง่ายพังตอนไหน |
| ก่อนแก้แต่ละไฟล์ | ไฟล์นี้มีหน้าที่อะไรในระบบ และการแก้นี้กระทบใครที่เรียกมันบ้าง |
| implementer ส่ง slice กลับ | เดินผ่านโค้ดที่เพิ่มทีละช่วง ชี้ `file:บรรทัด` ที่ควรอ่านก่อน |
| แก้บั๊ก: เจอต้นเหตุ | กลไกที่ทำให้พังทีละขั้นด้วยค่าจริง และสัญญาณที่จะทำให้จับได้เร็วครั้งหน้า |
| test แดงแล้วเขียว | test นี้ปกป้องพฤติกรรมอะไร อ่าน assertion ให้ฟัง และถ้าวันหน้ามีคนทำพังมันจะแดงยังไง |
| reviewer เจอปัญหา | ปัญหาแบบนี้เกิดจากอะไร และจะสังเกตเองได้ยังไง |
| เปลี่ยนแผนกลางทาง | สมมติฐานเดิมคืออะไร หลักฐานไหนหักล้าง และบทเรียนสำหรับครั้งหน้า |

ไม่ได้ใช้ agentic-engineering ให้สอนหลังแต่ละการเปลี่ยนที่มีความหมาย

## ส่วนที่เพิ่มในบล็อกสอนและรายงาน

- **อธิบายโค้ดใหม่ทีละบรรทัด** เฉพาะส่วนที่ใช้แนวคิดใหม่ ใส่โค้ดได้ถึงราว 20 บรรทัด แล้วอธิบายเป็นช่วง ๆ ว่าแต่ละช่วงทำอะไร
- **รันให้ดู** พฤติกรรมที่เป็นหัวใจของแนวคิด ให้รันตัวอย่างเล็ก ๆ แปะ output จริง แล้วชี้ว่าดูตรงไหน
- **"ถ้าไม่ทำแบบนี้จะเกิดอะไร"** ทุกการเปลี่ยนใน "ทำอะไรไปบ้าง" บอกผลที่ผู้ใช้ปลายทางจะเจอถ้าไม่แก้ หรือถ้าแก้ด้วยทางที่ง่ายกว่า
- **ศัพท์ทุกคำ** ศัพท์เทคนิคที่ไม่ใช่พื้นฐาน อธิบายในวงเล็บครั้งแรกที่ใช้ แม้จะไม่ใช่แนวคิดหลักของงาน
- **สมุดบันทึก** เปิด `.learning/journal.md` อัตโนมัติ

## งานเล็ก

แม้ระดับละเอียด งานที่ diff ไม่กี่บรรทัดก็สอนเฉพาะสิ่งที่มีให้เรียนจริง ข้อความทั้งหมดต้องได้สัดส่วนกับขนาดงาน แต่ "ทำอะไรไปบ้าง" ต้องครบทุกการเปลี่ยนเสมอ
