## `.learning/concepts.md`

```markdown
# แนวคิดในโปรเจกต์นี้

| แนวคิด | ความหมายสั้น | เจอที่ | ครั้งแรก | สถานะ | หลักฐานล่าสุด |
| --- | --- | --- | --- | --- | --- |
| debounce | รอให้ผู้ใช้หยุดพิมพ์สักพักก่อนค่อยทำงาน แทนทำทุกครั้งที่กดปุ่ม | `search/input.ts:14` | 2026-10-30 | เพิ่งเจอ | อธิบายตอนแก้ช่องค้นหายิง API รัว |
| state machine | เก็บสถานะเป็นค่าเดียวที่เปลี่ยนตามกฎ แทน boolean หลายตัว | `order/state.ts:10` | 2026-10-30 | เริ่มเข้าใจ | ตอบ "ทดสอบฉัน" ข้อ 2 ถูก |
```

สถานะ: `เพิ่งเจอ` (เราอธิบายแล้ว) → `เริ่มเข้าใจ` (เขาตอบคำถามถูกหรืออธิบายกลับได้) → `คล่อง` (เขาเขียนหรือแก้ส่วนที่ใช้แนวคิดนี้ได้เอง) ขยับเฉพาะเมื่อมีหลักฐาน

## `.learning/journal.md`

ใช้เฉพาะเมื่อผู้ใช้สั่ง "จดบันทึก" หรือเปิดโหมดสอนละเอียด

เพิ่มที่ท้ายไฟล์ งานละหนึ่งหัวข้อ:

```markdown
## 2026-10-30 แก้ช่องค้นหายิง API ทุกครั้งที่กดปุ่ม

- เป้าหมาย: ค้นหาลื่นขึ้น และไม่โดน rate limit ของ API
- ต้นเหตุ: `onChange` เรียก `fetchResults` ตรง ๆ ทุกตัวอักษร (`search/input.ts:14`)
- แนวคิดที่เจอ: debounce, การยกเลิก request เก่า (AbortController)
- เส้นทางอ่านโค้ด: `search/input.ts` → `search/api.ts` → `search/input.test.ts`
- คำถามที่ยังค้าง: ควรรอกี่ ms ถึงจะพอดี
- อ่านต่อได้: ความต่างระหว่าง debounce กับ throttle
```
