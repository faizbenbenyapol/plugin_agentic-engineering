# ตั้งโปรเจกต์และเปลี่ยนบทเรียนเป็นระบบ

## เปลี่ยนบทเรียนเป็นระบบ

- **บอก AI เรื่องเดิมเป็นครั้งที่ 2** ให้เปลี่ยนเป็นของที่บังคับได้ เรียงจากสูงไปต่ำ: สถาปัตยกรรมที่ทำให้ผิดไม่ได้ → type → lint/CI ที่ข้อความ error บอกว่าให้ใช้อะไรแทน → test → กฎใน `CLAUDE.md` (สุดท้าย ใช้กับเรื่องที่ต้องใช้วิจารณญาณเท่านั้น) ขั้นตอนเต็มใน `playbooks/correct.md` คำสั่งที่ต้องพูดซ้ำคืออาการ โครงสร้างคือการรักษา
- **งานไม่จิ๊บจ๊อยให้สร้างคานงัด** codemod, script, generator หรือ script ตรวจ ทำหน่วยแรกด้วยมือเพื่อเรียนสูตร แล้วเขียนเครื่องมือ พิสูจน์โดยรันกับหน่วยแรกแล้ว diff กับของที่ทำมือ ถ้าอ้างหลักการนี้แต่ไม่มีไฟล์เครื่องมือใน diff แปลว่ายังไม่ได้ทำ
- **งานตรวจที่ทำเป็นรอบ** (test ทุกคืน, รีวิว PR ตาม checklist, เช็กเอกสารล้าสมัย) ทำเป็น scheduled task หรือ routine

## ของที่โปรเจกต์ควรมี

ถ้ายังไม่มี ให้เสนอสร้างหนึ่งครั้งต่อโปรเจกต์ (ถามก่อน งานระดับเบาไม่ต้องเสนอ ถ้าผู้ใช้ไม่อยู่ ให้เขียนข้อเสนอหนึ่งบรรทัดในรายงาน ไม่ต้องรอ):

```markdown
# CLAUDE.md
## คำสั่ง
- ติดตั้ง / รัน dev / test / lint / typecheck: ...
- ตรวจแอปจริง: ใช้สกิล verify-<app> (ถ้ามี)
## แผนที่โปรเจกต์ (สั้น อัปเดตเมื่อโครงสร้างเปลี่ยน)
- src/core/    : logic หลัก ไม่ import UI/DB
- src/adapters/: ต่อ DB, API ภายนอก
- src/ui/      : หน้าจอ
## ข้อตกลง
- ...
## กฎและสิ่งที่บังคับใช้ (เพิ่มเมื่อ AI พลาดเรื่องเดิมซ้ำ)
| กฎ | บังคับด้วย |
| --- | --- |
| ห้าม import DB ใน src/core | lint rule `no-restricted-imports` |
| ... | เอกสารเท่านั้น (ต้องใช้วิจารณญาณ) |
```

และ `docs/specs/`, `docs/decisions/`, `docs/progress.md`, `.claude/skills/verify-<app>/` ตามที่งานต้องใช้ ไม่ต้องสร้างทั้งหมดตั้งแต่วันแรก
