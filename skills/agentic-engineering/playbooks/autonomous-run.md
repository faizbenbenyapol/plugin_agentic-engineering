# รันยาวจนจบ

**เราเป็นเจ้าของเงื่อนไขจบ กำหนด "เสร็จ" ก่อน แล้วขับไปถึงโดยไม่หยุด**

ใช้กับ: "ทำจนกว่า test จะเขียว" "ไปนอนแล้ว ทำต่อ" "วนจนกว่าจะผ่าน" งานเดียวที่มีเงื่อนไขจบชัด (งานโปรแกรมหลาย PR ใช้ `playbooks/large-task.md`)

## ขั้น

1. **ถ้าผู้ใช้ยังอยู่ ทำ `playbooks/kickoff.md` ก่อนปล่อยรัน** ถามเรื่องที่จะต้องตัดสินระหว่างทางให้หมดตอนนี้ เพราะหลังปล่อยรันแล้วจะไม่มีใครตอบ
2. **เขียนเงื่อนไขจบเป็นประโยคที่ตรวจได้ และเพดานรอบ** (ค่าเริ่มต้น 5 รอบ เว้นแต่ผู้ใช้กำหนดเอง) ก่อนรอบแรก เช่น test เขียวทั้งหมด, ขั้นตอนทำซ้ำบั๊กผ่าน, PR ทั้ง N ผ่าน CI, pixel diff เป็น 0
3. **เลือกกลไกปลุก** ถ้ามีเหตุการณ์ให้รอ (CI, merge) ใช้คำสั่งที่รอเหตุการณ์ หรือ agent เบื้องหลังที่แจ้งเมื่อเกิด ถ้าไม่มี ใช้รอบเวลาที่ห่างที่สุดเท่าที่รับได้ (`/loop` หรือ scheduled task ตามที่มี) เพราะแต่ละรอบใน session ส่ง context ทั้งหมดซ้ำ
4. **แต่ละรอบเปลี่ยนเล็กที่สุดที่หลักฐานรองรับ** ตรวจเทียบเงื่อนไข ขยับก็ commit ไม่ช่วยก็ทิ้ง ของ "เผื่อไว้" ให้ถอย ไม่ปล่อยติดไป ตรวจทีละหน่วยก่อนไปหน่วยถัดไป
5. **ปัญหาที่เจอระหว่างทางที่ขวางเป้าหมายเป็นของเรา** สกิลพัง บั๊กที่เกี่ยว ตัวตรวจที่ flaky เครื่องมือล้ม แก้เองเป็นงานแยก (commit หรือ PR ของมันเอง) แล้วกลับมาที่เป้าหมายหลัก ไม่จอดงานที่ย้อนได้ไว้รอผู้ใช้ แจ้งเฉพาะ: การกระทำที่ย้อนไม่ได้ (รายการหยุดรอยืนยันใน SKILL.md), เรื่องที่ผู้ใช้ต้องตัดสินซึ่งข้อตกลงงานไม่ได้ครอบ (ใช้ทางที่ย้อนได้ จดเป็นสมมติฐานรอยืนยัน แล้วทำต่อ ตาม kickoff), และทางตันจริง
6. **บันทึกทุกรอบ** ลง decision log (`references/decision-log.md`) แถวละรอบ: เปลี่ยนอะไร เงื่อนไขขยับไหม
7. **หยุดเมื่อถึงเงื่อนไขหรือเพดานรอบ** ที่ราบให้เปลี่ยนวิธีภายในเพดาน ถึงเพดานหรือทางตันให้รายงาน ไม่วนเปล่า ห้ามลดเงื่อนไขเพื่อประกาศชัยชนะ

**รายงาน:** เงื่อนไขจบ จำนวนรอบ อะไรลง อะไรทิ้ง สถานะเงื่อนไขสุดท้าย path ของ decision log และหัวข้อ "ควรดู"
