# แก้นิสัยพลาดซ้ำ

ผู้ใช้ต้องแก้ AI ในโปรเจกต์นี้เรื่องเดิมซ้ำ ๆ เป้าหมายคือเปลี่ยน repo จน agent ตัวถัดไปพลาดแบบนั้นไม่ได้

ให้สมมติว่าคนแก้โค้ดทุกคนคือ agent ที่เห็นแค่ไฟล์ที่ตัวเองเปิด ก๊อปตัวอย่างที่ใกล้ที่สุด และเลือกทางที่สั้นที่สุดที่คอมไพล์ผ่าน ออกแบบ repo ให้การเปลี่ยนที่ดูถูกจากไฟล์เดียว ถูกสำหรับทั้ง repo

## ขั้น

1. **หาประเภทของความผิดพลาด** อ่าน commit ล่าสุด, revert, คอมเมนต์รีวิว, `CLAUDE.md` และคอมเมนต์ที่อธิบาย workaround จัดกลุ่มเป็นประเภท ประเภทที่เกิด 2 ครั้งขึ้นไปนับ
2. **แก้แต่ละประเภทที่ชั้นสูงสุดที่ใช้ได้** ลองจากบนลงล่าง:
   1. **สถาปัตยกรรมทำให้ผิดไม่ได้** state แต่ละชิ้นมีเจ้าของเดียว งานแต่ละอย่างมีทางเดียวที่รองรับ ซ่อนไส้ในจน import ผิดแล้วพัง ใช้แหล่งความจริงเดียวแทนรายการที่ต้องซิงก์มือ ลบทางเก่าและโค้ดตายที่ agent จะก๊อป
   2. **type ทำให้เขียน state ผิดไม่ได้** ถ้ายังคอมไพล์ผ่าน ให้เพิ่ม lint หรือ CI check ที่ข้อความ error บอกไฟล์ type หรือฟังก์ชันที่ต้องใช้แทน ถ้ารูปแบบผิดมีเยอะอยู่แล้ว ให้ fail เฉพาะเมื่อการเปลี่ยนเพิ่มจำนวน
   3. **test พฤติกรรม** แก้หรือลบ test ที่ยังผ่านเมื่อพฤติกรรมพัง หรือพังเมื่อแค่ไส้ในเปลี่ยน
   4. **เอกสารหรือกฎใน `CLAUDE.md` เป็นทางสุดท้าย** ใช้เฉพาะเรื่องที่ต้องใช้วิจารณญาณ เพราะ agent ข้ามแล้วไม่มีอะไรพัง กฎที่ต้องใช้วิจารณญาณให้เขียนให้เด่นและแนบตัวอย่างความผิดพลาดจริง
3. **แก้และพิสูจน์** แก้ประเภทที่เกิดบ่อยที่สุดก่อน commit ละประเภท พิสูจน์ว่า check ใหม่ fail กับความผิดพลาดจริงในอดีต (checkout commit เก่าหรือใส่โค้ดผิดกลับเข้าไปแล้วรัน) คำสั่งเดียวกันต้องรันได้ทั้งในเครื่องและ CI ข้อยกเว้นให้ใส่ที่บรรทัดนั้นพร้อมเหตุผล วันหมดอายุ และการอนุมัติของมนุษย์
4. **รักษาตารางกฎ** ใน `CLAUDE.md` จับคู่กฎแต่ละข้อกับสิ่งที่บังคับใช้ (ดูแม่แบบใน `references/project-setup.md`) เมื่อผู้ใช้แก้เรา ให้แก้ความผิดพลาดแล้วเพิ่มกฎ ถ้ากฎมีอยู่แล้วแต่ไม่มีอะไรบังคับ นั่นคือการพลาดซ้ำ ให้แก้ที่ชั้นสูงสุดในการเปลี่ยนเดียวกัน ลบกฎเมื่อความผิดพลาดนั้นเกิดไม่ได้แล้ว
5. ทำ `playbooks/delivery.md`

**รายงาน:** แต่ละประเภทพร้อมหลักฐาน (commit/คอมเมนต์ที่เกิด) ชั้นที่เลือก และทำไมชั้นที่สูงกว่าใช้ไม่ได้ พร้อม output ที่แสดงว่า check ใหม่ fail กับความผิดพลาดเก่า
