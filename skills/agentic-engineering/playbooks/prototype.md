# Prototype

**เราเป็นเจ้าของการตัดสินใจ ไม่ใช่โค้ด** prototype คือเครื่องมือทิ้ง ของจริงสร้างต่อด้วย playbook ฟีเจอร์

playbook เดียวที่ "diff เล็กที่สุด" และมาตรฐานคุณภาพโค้ดกลับหัว ความเร็วสำคัญกว่าความเนี้ยบ ไม่ต้องวางแผน ความเข้มงวดอยู่ที่การเลือกดีไซน์ที่ถูกด้วยต้นทุนต่ำ เสนอทางเลือกที่ผู้ใช้ไม่ได้ขอได้ ทิ้งแนวหนึ่งแล้วลองอีกแนวได้

ใช้เมื่อ: มีทางเลือกที่ตอบได้ด้วยการลองรัน (layout, interaction, ความหนาแน่น, พฤติกรรม, timing, แนวทางไหนเร็วกว่า) แทนการถามผู้ใช้

## ขั้น

1. **ตั้งการตัดสินใจที่ prototype นี้มีไว้ตอบ** ให้ชัด ไม่มีการตัดสินใจ = ไม่ต้องทำ prototype ไปทาง playbook ฟีเจอร์
2. **หาตัวอย่างอ้างอิงเมื่อพื้นที่ดีไซน์ยังเปิดกว้าง** หา prior art สรุปธีม สี layout ให้ผู้ใช้เลือกทิศก่อนสร้าง ข้ามได้ถ้าทิศชัดแล้ว
3. **สร้างของทิ้งในโฟลเดอร์ scratch แยกจาก source จริง** งานภาพใช้ HTML/CSS/JS ล้วนหรือ stack ที่เบาที่สุด dependency จาก CDN และ dev server ที่ hot reload งานพฤติกรรมหรือ timing ใช้ script เล็กที่สุดที่ถามคำถามนั้นได้ ไม่ใช้ framework จริง ไม่มี test ไม่มี abstraction เขียนชัดว่าเป็นของทิ้ง
4. **ถ้าเทียบหลายแบบ ให้รวมไว้หลังตัวสลับเดียว** (ปุ่มหรือคีย์ลัด) แต่ละแบบมีป้ายชื่อ นี่คือการสำรวจทางเลือกให้สุดแบบต้นทุนต่ำ
5. **ตรวจบน surface จริง** งานภาพ: screenshot ทุกแบบและลองใช้ interaction งานพฤติกรรม: log เวลา พิมพ์ output หรือดู render การสังเกตคือ test ของ playbook นี้
6. **นำเสนอทางเลือก ข้อแลกเปลี่ยน และคำแนะนำ** เก็บข้อสรุปไว้ ทิ้งโค้ด ส่งทิศที่เลือกให้ playbook ฟีเจอร์สร้างจริง

**รายงาน:** แบบที่ลอง หลักฐาน (screenshot หรือ output/timing ที่สังเกตได้) ข้อแลกเปลี่ยน คำแนะนำของเรา path ของ scratch และบอกตรง ๆ ว่าเป็นของทิ้ง
