# รับงานต่อ / พักงาน

สองครึ่งของเรื่องเดียวกัน พักให้ดี คนที่มาทำต่อ (หรือ session ใหม่ของเราเอง) จะไม่ต้องเดา

## พักงาน

**เราเป็นเจ้าของการหยุดที่สะอาด** ทิ้ง checkpoint ที่ agent ที่เริ่มจากศูนย์หยิบต่อได้ ใช้เฉพาะเมื่อผู้ใช้สั่งพัก หรือบอกว่าจะปิดเครื่อง/รีสตาร์ต ถ้าผู้ใช้บอก "ทำต่อ" "ไปนอนแล้ว ทำต่อ" ห้ามพัก ถ้าแค่ context ใกล้เต็ม ให้ทำขั้น 4 (เขียนบันทึก) อย่างเดียวแล้วทำงานต่อ

1. **หยุดที่รอยต่อที่ปลอดภัย** ทำขั้นปัจจุบันให้จบหรือถอยออก ไม่เริ่มอะไรใหม่ ยกเลิก agent ที่ซ้อนอยู่
2. **ไม่ทำอะไรที่ย้อนไม่ได้เพื่อพัก** ไม่เปิด PR ไม่ push ถ้ายังไม่เคยมี
3. **ทำให้งานไม่หาย** commit การแก้ที่ค้างเป็น commit `wip:` เดียวบน branch ปัจจุบัน ถ้า tree พังอยู่ให้เขียนบอกใน body หนึ่งบรรทัด
4. **เขียนบันทึกสำหรับทำต่อลงไฟล์** `docs/progress.md` (หรือ path ที่ผู้ใช้กำหนด): เป้าหมาย, กำลังทำอะไร, ความคืบหน้าและอะไรตรวจแล้ว, สถานะปัจจุบัน, ขั้นต่อไป, ไฟล์สำคัญ, กับดักที่เจอ ถ้ามี decision log ให้ชี้ไปที่นั่นแทนเขียนซ้ำ

**รายงาน:** อยู่ตรงไหนของงาน อะไรอยู่บน disk แล้ว อะไรยังอยู่แค่ในหัว (บอก path ไม่แปะ diff) commit ที่ทำ tree สะอาดไหม และการกระทำแรกเมื่อกลับมา นี่คือการพัก ไม่ใช่รายงานจบงาน

## ทำต่อ

**เราเป็นเจ้าของจุดเริ่มต่อ อ่านร่องรอยเดิม อย่าทำซ้ำ**

1. **หาร่องรอยเดิม** `docs/progress.md`, decision log, branch ที่ push ไว้, `git log`, หรือสรุปที่ผู้ใช้ให้มา อ่านส่วนท้ายก่อนแล้วไล่ย้อนหาจุดตัดสินใจ ร่องรอยยาวให้ `scout` ย่อเป็นไทม์ไลน์
2. **สร้าง state กลับมา** branch และ worktree อะไรลงไปแล้ว (`git log`, `git diff` เทียบ base) task ที่ค้าง การตัดสินใจที่ทำแล้ว ร่องรอยเดิมคือข้อมูลที่เชื่อได้ อย่าอยากพิสูจน์ใหม่หมด
3. **เทียบเสร็จกับค้าง** ระบุจุดเริ่มต่อ ไม่รันการทำซ้ำเดิมใหม่ ไม่ทำงานที่เสร็จแล้วซ้ำ
4. **ส่งงานที่เหลือให้ playbook ที่ตรง** และเลือกว่าจะ: ทำต่อ, ส่งคำแนะนำที่เสร็จแล้ว, รับรองหรือกลับคำตัดสินเดิม, หรือสรุปบทเรียนของงานที่ล้ม playbook นี้จบตรงนี้
5. **ตรวจข้ออ้างที่รับมาเทียบเป้าหมายเดิมบนของจริง** รายงาน "ผ่าน" ของรอบก่อนไม่ใช่หลักฐาน

**รายงาน:** งานเดิมหยุดตรงไหน อะไรรับมา อะไรทำซ้ำ (ควรไม่มี) จุดเริ่มต่อ และผลลัพธ์
