# รีแฟกเตอร์

**เราเป็นเจ้าของสัญญา โครงสร้างเปลี่ยน พฤติกรรมไม่เปลี่ยน** ต่างจากฟีเจอร์ (เพิ่มพฤติกรรม) และแก้บั๊ก (แก้พฤติกรรม)

ถ้าระหว่างทางเจอฟีเจอร์ที่ขาดหรือบั๊กจริง ให้แยกออก ส่งการเปลี่ยนโครงสร้างก่อนโดยยึดสัญญาเดิม ถ้าจะออกแบบใหม่ทั้งก้อน ให้บอกตรง ๆ แล้วไปทาง playbook ฟีเจอร์ งานโครงสร้างใหญ่ข้ามหลายส่วนใช้ `playbooks/large-task.md`

## ขั้น

1. **ตรึงพฤติกรรมก่อน** สืบสวนส่วนที่จะแตะเพื่อรู้สัญญา แล้วเขียน characterization test, snapshot หรือ harness เทียบ output ที่จับพฤติกรรมปัจจุบันไว้ก่อนขยับอะไร พื้นที่ที่ไม่มี test ต้องเขียนตัวตรึงก่อนแตะ type check และ lint ไม่นับเป็นตัวตรึง
2. **ตั้งชื่อโครงสร้างที่โค้ดขาด** (หลักการ Model the Domain) โค้ดธรรมดาที่รูปชัดและอยู่ที่เดียวอยู่ต่อได้ การปรับรูปต้องลบ branch หรือ state ผิด ๆ ได้ ไม่ใช่เพิ่มชั้นอ้อม
3. **ตั้งชื่อรูปเป้าหมาย** ถ้าสร้างวันนี้ โมดูล type และ call graph ควรเป็นยังไง ถ้าข้ามขอบฟังก์ชันให้ร่างแบบตาม `references/design.md` ก่อนย้าย
4. **ลบก่อนเพิ่ม** เอาโค้ดตาย wrapper ที่มีผู้เรียกคนเดียว validator ซ้ำ และการอ้างอิงที่ไม่มีใช้ออกก่อน แล้วค่อยใส่รูปใหม่ ส่งแค่การเปลี่ยนที่เล็กที่สุดที่ถึงรูปเป้าหมาย การ cleanup ที่ "น่าจะช่วย" ให้ถอย
5. **ขยับทีละขั้นเล็ก ๆ ที่ตัวตรึงยังเขียว** API ที่เปลี่ยนรูป ให้ย้าย caller ทั้งหมดแล้วลบของเก่าในรอบเดียว ไม่มี shim ไม่ปล่อยสองทางอยู่คู่กัน ตรวจทุกการเปลี่ยนชื่อกับไฟล์จริง การ rename มักพลาดชื่อในสตริง เอกสาร และการอ้างอิงย้อนกลับ งาน mechanical หลายจุดให้เขียน codemod หรือ script (คานงัด) แล้วรันเองพร้อมขอบเขต: path, ชื่อที่ย้าย, พฤติกรรมที่ต้องคงไว้
6. **พิสูจน์ว่าพฤติกรรมเท่าเดิมบนของจริง** ไม่ใช่ "คอมไพล์ผ่าน" งานใหญ่ให้ทำ equivalence check: script เทียบ output เก่ากับใหม่ หรือ replay baseline ที่บันทึกไว้ test ชุดเดิมต้องผ่านโดยไม่แก้ test ถ้าต้องแก้ test แปลว่าพฤติกรรมเปลี่ยน ให้แจ้งผู้ใช้
7. **ยืนยันว่าคุ้มเก็บ** ตัววัดคือภาระคนอ่านลดลง (จำนวนชั้นที่ต้องไล่ และ state ที่ต้องจำ) ถ้า diff ไม่ทำให้ภาระลดลงที่ไหนเลย ให้ถอย
8. **ทำ `playbooks/delivery.md`** commit เล็กเรียงลำดับ: commit ลบก่อน ตามด้วยการปรับรูป แล้วค่อย cleanup ต่อเนื่อง

**รายงาน:** โครงสร้างที่เปลี่ยน ตัวตรึงที่ใช้ยึด หลักฐานว่าเท่าเดิม ภาระคนอ่านที่ลดลง (ก่อน → หลัง) อะไรส่ง อะไรถอย ไม่มีพฤติกรรมใหม่
