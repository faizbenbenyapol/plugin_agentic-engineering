# ตั้งโจทย์ร่วม และถามกลับระหว่างทาง

**ผู้ใช้กับ agent ต้องเข้าใจงานตรงกันก่อนลงมือ** ทั้งข้างนอก (ผลที่ผู้ใช้จะเห็น) และข้างใน (โค้ดส่วนไหนจะเปลี่ยน อย่างไร ทำไม) งานจึงเป็นกล่องใส (white box) ไม่ใช่กล่องดำที่ผู้ใช้สั่งแล้วไม่รู้ว่า agent ทำอะไรลงไป เมื่อตกลงกันแล้ว agent ทำงานยาวได้โดยไม่ต้องหยุดถามเรื่องที่ตกลงไว้

ใช้กับ: ฟีเจอร์, งานใหญ่, งานรันยาว, รีแฟกเตอร์ที่เปลี่ยนสิ่งที่ผู้ใช้เห็น, บั๊กที่ "พฤติกรรมที่ถูก" ยังไม่ชัด และคำขอที่ตีความได้หลายแบบ

ข้ามได้: งานเบา, บั๊กที่พฤติกรรมที่ถูกชัดอยู่แล้ว (test หรือสเปกบอกไว้), งานอ่านอย่างเดียว และเมื่อผู้ใช้สั่ง "ตัดสินใจเองได้"

## ขั้น

1. **สำรวจก่อนถาม** อ่านโค้ดส่วนที่เกี่ยวแบบแคบ เพื่อถามเฉพาะสิ่งที่โค้ดตอบไม่ได้ ห้ามถามสิ่งที่หาเองได้ (ภาษา framework มี test ไหม ใครเรียกฟังก์ชันนี้)

2. **ทวนความเข้าใจ** เขียน "ผมเข้าใจว่า" ด้วยภาษาธรรมดา: ทำเพื่อใคร เสร็จแล้วผู้ใช้จะเห็นอะไร และส่วนของระบบที่จะแตะ (ไฟล์ละหนึ่งบรรทัดว่ามีหน้าที่อะไร) ส่วนนี้ใช้แทน "แผนที่งาน" ของ learn-while-building ได้

3. **ถามเป็นรอบ** เรียงตามต้นทุนถ้าเดาผิด เรื่องที่แก้ทีหลังแพงถามก่อน ครอบคลุมหมวดเหล่านี้เท่าที่งานมีเรื่องเปิด:
   - **เป้าหมายและผู้ใช้:** ใครใช้ ใช้ตอนไหน ปัญหาจริงคืออะไร
   - **ขอบเขต:** ทำอะไร ไม่ทำอะไรในรอบนี้ ฟีเจอร์ย่อยที่เราคิดว่าควรมีแต่ผู้ใช้ไม่ได้พูด ต้องถามว่า "อันนี้ทำด้วยไหม" ทุกข้อ
   - **พฤติกรรมและกรณีขอบ:** ค่าว่าง ค่าผิดรูป ข้อมูลซ้ำ ทำพร้อมกัน error แล้วผู้ใช้เห็นอะไร
   - **ข้อมูลและกฎธุรกิจ:** ตัวเลข การปัดเศษ สิทธิ์ เงิน เวลาและเขตเวลา
   - **ข้อจำกัด:** library ที่ห้ามหรือต้องใช้ ความเร็ว ความเข้ากันได้กับของเดิม
   - **เกณฑ์เสร็จ:** ผู้ใช้จะตรวจยังไงว่าเสร็จ (ขั้นตอนที่กดหรือคำสั่งที่รัน)
   - **วิธีทำงาน:** ให้ถามระหว่างทาง หรือทำยาวแล้วสรุปทีเดียว อยากเห็น checkpoint ตรงไหน

   ทุกคำถามมี 3 ส่วน ผู้ใช้จึงตอบได้เร็วและเรียนไปด้วย:
   - **ทำไมต้องถาม:** ถ้าเลือกผิด จะเกิดอะไร
   - **ตัวเลือก 2–4 ข้อ** พร้อมข้อแลกเปลี่ยนสั้น ๆ
   - **คำแนะนำของเรา** เป็นตัวเลือกแรก พร้อมเหตุผล

   มีเครื่องมือถามแบบตัวเลือก (เช่น AskUserQuestion) ให้ใช้ ครั้งละไม่เกิน 4 ข้อ เกินให้แบ่งรอบ ผู้ใช้ตอบ "ตามที่แนะนำ" แปลว่ารับค่าแนะนำทุกข้อที่ยังไม่ได้ตอบ

   **หยุดถาม** เมื่อเรื่องที่เหลือเดาผิดแล้วแก้ง่ายและไม่เปลี่ยนสิ่งที่ผู้ใช้เห็น เรื่องพวกนั้นตัดสินเองแล้วจดเป็นสมมติฐาน ห้ามถามเพื่อโยนการตัดสินใจทางเทคนิคที่เราควรรู้ดีกว่า

4. **เขียนข้อตกลงงาน** นี่คือความจริงชุดเดียวที่ทั้งสองฝ่ายใช้อ้าง:

   ```
   **ข้อตกลงงาน: <ชื่องาน>**
   - เป้าหมาย / ใครได้อะไร:
   - ทำ:
   - ไม่ทำรอบนี้:
   - พฤติกรรมและกรณีขอบ:
   - เกณฑ์เสร็จ (ตรวจยังไง):
   - แผน: ขั้น 1..n แต่ละขั้นแตะอะไร (ไฟล์หรือโมดูล) และพิสูจน์ยังไง
   - ผมตัดสินเองได้: <เรื่องเทคนิคที่ย้อนได้ และไม่เปลี่ยนสิ่งที่ผู้ใช้เห็น>
   - จะกลับมาถามเมื่อ: <เรื่องที่ยังเปิด หรือสถานการณ์ที่ต้องให้ผู้ใช้ตัดสิน>
   - สมมติฐานที่ใช้: <...>
   ```

   ระดับกลางเขียนในแชท งานใหญ่ งานรันยาว หรืองานข้าม session เก็บที่ `docs/specs/<ชื่อ>.md` ด้วย เพื่อให้กลับมาอ่านได้ทั้งผู้ใช้และ session ถัดไป

5. **รอยืนยันหนึ่งครั้ง แล้วลงมือยาว** ผู้ใช้อยู่: รอคำตอบก่อนแก้ไฟล์แรก ผู้ใช้ไม่อยู่ (scheduled task หรือบอกว่าจะกลับมาดู): ใช้ค่าแนะนำทุกข้อ ติดป้าย **รอยืนยัน** ที่ข้อตกลงไว้บนสุดของรายงาน แล้วทำต่อเฉพาะส่วนที่ย้อนได้

## ระหว่างทำ: ถามกลับเมื่อไม่แน่ใจ

แยกความไม่แน่ใจเป็น 3 แบบก่อนตัดสินว่าจะถามไหม:

| แบบ | ตัวอย่าง | ทำ |
| --- | --- | --- |
| หาเองได้ | ฟังก์ชันนี้ใครเรียก library ทำแบบนี้จริงไหม | อ่านหรือรันเอง ห้ามถาม |
| เทคนิคที่ย้อนได้ และผู้ใช้ไม่เห็นความต่าง | ชื่อตัวแปร แยกไฟล์ไหน ใช้ Map หรือ object | ตัดสินเอง แล้วอธิบายเหตุผลในบล็อกสอน |
| ผู้ใช้ต้องตัดสิน | พฤติกรรมที่ข้อตกลงไม่ได้พูดถึง เพิ่มหรือตัดฟีเจอร์ กฎธุรกิจ หน้าตาและการใช้งาน สถาปัตยกรรม หรือเจอว่าข้อตกลงเดิมผิด | ถาม ห้ามเดา |

- **ถามแบบเดียวกับขั้น 3:** ทำไมต้องถาม ตัวเลือก และคำแนะนำ พร้อมบอกว่าเจออะไรถึงต้องถาม
- **ผู้ใช้อยู่:** ถามทันที งานส่วนที่ไม่ขึ้นกับคำตอบทำต่อได้ ส่วนที่ขึ้นกับคำตอบให้รอ
- **ผู้ใช้ไม่อยู่:** เลือกทางที่ปลอดภัยและย้อนได้ที่สุด จดเป็น "สมมติฐานรอยืนยัน" ลง decision log (`references/decision-log.md`) แล้วทำต่อ รายงานไว้บนสุดตอนจบ
- **เจองานที่น่าทำแต่อยู่นอกข้อตกลง** ห้ามทำเงียบ ๆ ถามว่า "อันนี้ทำด้วยไหม" ถ้าผู้ใช้อยู่ ไม่งั้นเขียนเป็นข้อเสนอท้ายรายงาน
- **ข้อตกลงเปลี่ยน** อัปเดตข้อตกลง (และไฟล์ถ้ามี) แล้วบอกหนึ่งบรรทัดว่าเปลี่ยนข้อไหนเพราะอะไร
- **งานยาว** ส่ง checkpoint สั้น ๆ ตามจุดที่ตกลงไว้: ทำอะไรเสร็จ ตัดสินอะไรไปเอง ต่อไปจะทำอะไร

## ระดับการถาม

| ผู้ใช้พูด | ผล |
| --- | --- |
| "ถามละเอียด" (ค่าเริ่มต้น) | ตามไฟล์นี้ทั้งหมด |
| "ตัดสินใจเองได้" | ข้ามขั้น 3 ใช้ค่าแนะนำแล้วเขียนข้อตกลงให้อ่านก่อนเริ่ม ระหว่างทางถามเฉพาะรายการหยุดรอยืนยันใน SKILL.md ข้อ 5 และเรื่องที่ทำให้ข้อตกลงผิด ที่เหลือจดเป็นสมมติฐาน |

ถ้าผู้ใช้บอกให้จำ ให้บันทึกในโปรไฟล์ผู้เรียน (`ระดับการถาม:`)

## รายงานจบงาน

เพิ่มหัวข้อ **ใครตัดสินอะไร** ในรายงาน:
- ผู้ใช้ตัดสิน: <ข้อที่ตอบในขั้น 3 หรือระหว่างทาง>
- ผมตัดสินเอง: <เรื่อง + เหตุผลหนึ่งบรรทัด>
- ยังรอยืนยัน: <สมมติฐานที่ใช้ไป และผลถ้าคำตอบต่างออกไป>

และเทียบ **เกณฑ์เสร็จ** ในข้อตกลงทีละข้อ: ผ่าน / ไม่ผ่าน / สรุปไม่ได้ พร้อมหลักฐาน
